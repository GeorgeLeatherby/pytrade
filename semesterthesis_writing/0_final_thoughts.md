## RESOLVED (2026-10-12): Feature, accounting, training and integration audit

The twelve findings below are now addressed in code. This section supersedes the earlier decision to preserve dollar-valued SAA feedback and the corresponding claim that SAA retraining is unnecessary. The October 11 replay figures describe the previous implementation only; they are not verification results for the corrected observations, features or rewards.

1. **PAA allocation bounds.** All three allocator families use the shared configurable `allocator_action_logit_bound`, defaulting to 5.0. With eleven risky assets and the unchanged fixed cash logit of zero, bounds [-5, 5] permit a maximum cash target of approximately 93.10%. This is target reachability, not a guarantee of immediate execution under the existing partial-rebalancing mechanics. Initial Gaussian exploration is not rescaled by widening these bounds.

2. **Terminal observations and bootstrapping.** Truncated and terminated episodes return actual final market/portfolio observations rather than zero vectors. Final specialist observations and shadow holding fractions are preserved before vectorized auto-reset. Hierarchical terminal signals are predicted using copied recurrent state, without executing terminal trades or altering the reset episode's memory. AR(1) terminal signals use the final process update without committing another shadow trade; zero-signal terminal columns remain zero. PPO and RecurrentPPO therefore bootstrap ordinary time limits from real final-state inputs.

3. **FFD exclusion of test data.** FFD order selection and stationarity acceptance use only dates before the final 252 unique market dates. The selected order and finite filter weights are then applied causally throughout the complete dataset. The market cache also reserves exactly the last 252 dates for testing, independently of the configured training episode length. Cleaning cannot silently move the reserved test boundary: generation fails if those final dates change. Dataset generation writes a metadata sidecar recording feature schema version 2, ordered columns, FFD order/weights and the fit/test dates. This fixes test-period fitting leakage; pre-test validation data still participates in preprocessing selection, so it is not a train-only validation-preprocessing claim.

4. **FFD filter direction.** The filter uses correlation with the existing oldest-to-newest weight ordering, avoiding convolution's second reversal. The reviewed [1, 2, 4] example with weights [-0.125, -0.5, 1] now produces 2.875. Per-symbol index alignment and insufficient-history handling are retained.

5. **Volatility-breakout features.** Breakout is the per-symbol trailing z-score of the log ratio of five-day to 36-day volatility, calculated separately for each configured return horizon and clipped to [-4, 4]. The SPY-relative return basis is intentionally retained. Consequently, SPY's own relative-volatility feature remains zero by design rather than being presented as an absolute SPY-volatility signal. The earlier mixed-unit formula and its almost-constant -4 outputs are removed.

6. **Cash/holding observation encoding.** SAA cash and asset values use `log1p(notional / initial_capital)`. Empty holdings encode as zero, while holdings equal to initial capital encode as log(2), eliminating the previous empty-versus-fully-funded ambiguity. The number and ordering of observation fields are unchanged, but their meaning changes and old normalization statistics must not be reused.

7. **SAA return and executed-action accounting.** SAA feedback is now net percentage NAV return, including charged transaction costs and positive cash interest, with self-financing buys/sells excluded from profit. Standalone and isolated shadow accounts share this calculation. Generic shadow feedback follows the same percentage convention. Execution-gap penalties use signed executed shares times execution price, excluding subsequent market-price movement. The minimum-trade deadband is expressed in already-scaled action units without the former extra inverse-limiter division. A hold during a price gain no longer attracts a false execution-gap penalty.

8. **Risk timing and drawdown reporting.** Today's NAV, weights, positions, prices and return are snapshotted before reward risk calculations. Return/drawdown windows include the current step and respect lookback offsets while excluding padding. Rolling drawdown levels are stored separately from incremental drawdown penalties. Whole-episode drawdown is calculated directly from the complete NAV curve, including the initial-capital reference, rather than taking the largest penalty increment or returning zero for SAA episodes. Shadow drawdown uses immutable pre-action NAV snapshots, so later balance mutations cannot erase transaction-cost losses from history.

9. **Sortino denominator units.** The PAA reward now uses a downside standard-deviation floor of 0.005, equivalently a variance floor of 0.000025, matching the SAA and shadow estimators. EMA settings and configured reward coefficients are preserved. The prior effective 7.07% standard-deviation floor is removed; reward-component magnitudes should be checked during the new training/validation runs.

10. **Matched AR(1) shadow execution and affordability.** AR(1) shadows now use real isolated single-asset environments with the selected SAA's execution configuration and account capital, without loading or running a specialist model. Only action origin differs between AR(1) and hierarchical shadow execution. All four AR(1) configurations explicitly declare `shadow_execution_config_path`; it currently points to specialist configuration 01056, matching the current hierarchical references. Training and inference read the same path. If the new specialist uses another configuration, update these paths to match it. Generic shadow buys also reserve costs through bounded affordability sizing, including fixed fees. Live PAA execution settings are unchanged, and the zero ablation still never trades its shadow accounts.

11. **Volume benchmark and horizons.** Negative SPY log-volume intensity is no longer clipped before subtraction. Horizon p measures log(mean volume over p days / mean volume over 36 days); the same-horizon SPY value is subtracted before trailing normalization. The 1-, 5- and 21-day inputs are now genuinely different on changing volume, while SPY-relative volume is correctly zero for SPY itself.

12. **SAA validation normalization.** The custom SAA validation callback synchronizes training observation/reward statistics into the frozen evaluation wrapper before every deterministic sweep. Evaluation remains non-updating and reports raw rewards. Fresh and continued-training paths therefore use current training normalization for checkpoint selection, rather than initial or stale statistics.

13. **SPY market-context input for SAA.** Standalone SAA observations now optionally include one scalar `SPY` same-day `log_close_return_1d` input, controlled by `environment.include_spy_log_close_return_1d`. It is derived directly from the cached SPY closes in O(1) time rather than duplicated across every asset feature row. The PAA hierarchical SAA shadow wrapper uses the same standalone environment and therefore receives the identical input automatically; its observation-shape compatibility check remains active. The new `config_01056` enables this input. Existing checkpoints/configurations without the flag retain their previous observation shape. The changed observation requires fresh SAA normalization statistics and retraining of dependent PAA runs; old SAA/PAA checkpoints must not be reused.
